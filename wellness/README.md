# wellness/ · ERKAK на erkak.com

Мировая экосистема мужского велнеса на девяти языках (ru, en, de, ar, zh, ja, ko, th, uz): 14 направлений, топ-100 программ, 14 мест, 9 гайдов. Раздел рыбалки уже продаётся, остальные программы работают как предзапись.

Сайт статический и генерируется одним скриптом, API заявок работает на Node 22. Внешних зависимостей нет.

Стратегия:
- экосистема: [ECOSYSTEM.md](ECOSYSTEM.md);
- рыбалка, ниша и конкуренты: [STRATEGY-fishing.md](STRATEGY-fishing.md);
- правила перевода: [content/TRANSLATING.md](content/TRANSLATING.md).

### Адреса

| Путь | Страница |
|---|---|
| `/` | Выбор языка (x-default): сохранённый язык или язык браузера |
| `/{ru,en,de,ar,zh,uz}/` | Главная на каждом языке |
| `/{яз}/fishing/`, `/{яз}/fishing/<тур>/` | Раздел рыбалки и 12 туров |
| `/{яз}/fishing/map/` | Где можно рыбачить в Таиланде: карта районов, точек и запретных зон |
| `/{яз}/pay/done/` | После оплаты в Stripe (служебная, не индексируется) |
| `/{яз}/<направление>/`, `/{яз}/<направление>/<программа>/` | 13 направлений и 88 программ |
| `/{яз}/destinations/…`, `/{яз}/guides/…` | Места и гайды |
| `/{яз}/about/`, `/terms/`, `/privacy/` | О нас (там же визовая поддержка) и документы |

Слаги английские и одинаковые во всех языках, поэтому hreflang связывает страницы один к одному.

Что генерируется помимо страниц:
- `sitemap.xml` (индекс) и `sitemap-<яз>.xml` с `xhtml:link`;
- `robots.txt`, `llms.txt`, `manifest.webmanifest`;
- ключ IndexNow;
- многоязычный `404.html`.

Все CSS и JS получают хеш в имени (`/assets/<имя>.<хеш>.<ext>`), поэтому их можно кэшировать на год.

## Команды

```bash
cd wellness
node build.mjs                 # все языки → public/
node build.mjs --lang=ru       # один язык, быстро
node tools/check-i18n.mjs      # переводы против ru: ключи, длины списков, подстановки, ссылки, кириллица
node tools/check.mjs           # собранный сайт: ссылки, якоря, hreflang, title/description, canonical, JSON-LD, карты сайта
STATIC_DIR=public node server/leads.mjs   # http://localhost:8796: сайт и API заявок
node tools/og.mjs              # перерисовать OG-картинки и иконки (нужен Playwright)
node tools/fonts.mjs           # перекачать шрифты (нужен интернет)
node tools/generate.mjs        # сгенерировать кадры по content/PHOTO-PROMPTS.md → photos-src/ (Pollinations или Gemini)
node tools/photos.mjs          # свои кадры из photos-src/ и фото из content/photos.mjs → src/img/photos/*.webp
```

Если язык ещё не переведён или перевод не собирается, сборка его пропускает и пишет предупреждение. При `STRICT=1` (так работает деплой) такой язык считается ошибкой.

## Как править

- **Текст:** правьте `content/<язык>/…`, затем `node tools/check-i18n.mjs <язык>`.
- **Цена, сезон, длительность, статус:** правьте `content/core.mjs`, это сразу меняется на всех языках.
- **Новая программа:**
  1. Добавьте строку в `PROGRAMS` в `core.mjs`: `[id, слаг, направление, место, длительность, от $, месяцы, хит, за что]`.
  2. Добавьте тексты с этим `id` в `catalog.programs` каждого языка.
  3. Проверка покажет, где тексты пропущены.
- **Открыть продажи направления:** поставьте `status:'live'` у направления в `core.mjs`, тогда кнопки «Предзапись» станут бронированием.
- **Новый язык:**
  1. Добавьте его код в `SITE.langs`.
  2. Скопируйте папку `content/en` в `content/<код>` и переведите по `content/TRANSLATING.md`.
  3. Если нужен другой алфавит, добавьте шрифт в `tools/fonts.mjs`.

## Деплой на erkak.com

На сервере есть и другие проекты, поэтому выкладка идёт в два шага: сначала проверка, потом выкладка.

```bash
./deploy.sh wellness-check   # только смотрит сервер и печатает отчёт, ничего не меняет
./deploy.sh wellness         # та же проверка; выкладка — только если она прошла
```

Из GitHub: пуш в ветку запускает сборку и проверку сервера (только чтение). Выкладка — только тегом:

```bash
git tag deploy-wellness-2026-10-01 && git push origin deploy-wellness-2026-10-01
```

**Проверка останавливает выкладку, если:**
- `nginx -t` не проходит уже сейчас (сломан чужой конфиг);
- порт 80 держит не nginx;
- нет конфига `/etc/nginx/sites-available/erkak.com.conf` (другой путь: `NGINX_CONF=…`), в нём нет строки `root /var/www/erkak.com;` или домен описан ещё в каком-то конфиге;
- в `/var/www/erkak.com` лежит что-то кроме магазина или прежней версии ERKAK, или это ссылка на другую папку (если содержимое можно заменить: `ALLOW_UNKNOWN_WEBROOT=1`);
- порт 8796 занят чужим процессом или служба `erkak-wellness` запускает чужой код;
- node на сервере старше 22.13 (node не обновляется: им могут пользоваться другие проекты);
- нет `rsync`, пользователя `www-data` или места на диске.

**Что меняет выкладка (и больше ничего):**
1. Собирает все языки в строгом режиме и прогоняет обе проверки — ещё до обращения к серверу.
2. Загружает сайт и API в служебные папки рядом; рабочий сайт в это время не меняется.
3. Сохраняет резервную копию: сайт, конфиг домена, сниппет, `/opt/erkak-wellness`, служба → `/var/backups/erkak-wellness/<дата>.tgz` (последние 5).
4. Меняет папку `/var/www/erkak.com` целиком. Магазин переезжает в `/var/www/erkak.com-shop`, прежняя версия ERKAK — в `/var/www/.erkak.com-prev`. Папка `.well-known` (подтверждение сертификата) переносится.
5. Обновляет API заявок и оплаты в `/opt/erkak-wellness` (служба `erkak-wellness`, 127.0.0.1:8796).
6. Кладёт сниппет `/etc/nginx/snippets/erkak-wellness.conf` и добавляет одну строку `include` в конфиг erkak.com. nginx перезагружается (reload) только если `nginx -t` проходит.
7. Проверяет: страница `/ru/` отвечает 200, заявки проходят через nginx, **все другие сайты сервера отвечают так же, как до выкладки.**
8. Отправляет все адреса в IndexNow (Bing, Yandex, Seznam). Отключить: `NO_INDEXNOW=1`.

Если любой шаг 3–7 не прошёл (или оборвалась связь), всё возвращается как было: папки, конфиг, сниппет, служба. Порядок отката проверен на копии сервера, в том числе когда на домене был магазин.

Вручную вернуть прежнюю версию: `tar -xzf /var/backups/erkak-wellness/<дата>.tgz -C /` и `nginx -t && systemctl reload nginx`.

Если API недоступен, заявка не теряется: клиенту открывается Telegram или WhatsApp с готовым текстом.

## Заявки

Заявки приходят в Telegram-группу. Токен бота и ID группы задаются при деплое переменными окружения вашего терминала. Скрипт дописывает их в `/opt/erkak-wellness/.env` (права 600) и отправляет одно тестовое сообщение в группу:

```bash
TELEGRAM_BOT_TOKEN='…' LEADS_TG_CHAT='-100…' ./deploy.sh wellness
```

Токены не кладите в репозиторий: он публичный. Проверить бота на сервере: `cd /opt/erkak-wellness && set -a && . ./.env && node leads.mjs tg-test`.

Типы заявок:

| Тип | Откуда |
|---|---|
| `eco` | Квиз главной |
| `waitlist` | Предзапись на программу |
| `plan` | «Мой маршрут»: несколько программ одной заявкой |
| `quiz` | Квиз рыбалки |
| `tour` | Форма тура рыбалки |
| `guide` | Гайд по Андаману |

У каждой заявки сохраняются язык сайта, валюта, страница и UTM-метки.

```bash
cd /opt/erkak-wellness
DATA_DIR=data node leads.mjs list 20
DATA_DIR=data node leads.mjs status 12 quoted "3 варианта отправлены"
DATA_DIR=data node leads.mjs stats            # воронка, источники, туры, языки за 30 дней
DATA_DIR=data node leads.mjs export 90 > leads.csv
```

## Оплата (Stripe)

На страницах туров рыбалки есть кнопка «Оплатить 30% картой». Туры «за группу» (турнир, Signature Week) оплачиваются только по счёту.

Как это работает:
1. Браузер отправляет тур, число гостей и контакт на `/api/checkout`.
2. Сервер считает сумму сам, по `server/prices.json`: этот файл пишет сборка из `content/core.mjs`.
3. Сервер создаёт Stripe Checkout, клиент платит на странице Stripe.
4. Вебхук `/api/stripe` проверяет подпись, ставит заявке статус `deposit` и пишет в Telegram «Предоплата получена».

Если ключа Stripe на сервере нет, кнопка честно отправляет обычную заявку.

Подключение:
1. Заведите аккаунт Stripe на юрлицо. Stripe работает с компаниями в Таиланде, ОАЭ, ЕС, США и ряде других стран. Карты российских банков Stripe не принимает, для них остаются перевод через партнёра, USDT и наличные.
2. В Stripe → Developers → Webhooks добавьте адрес `https://erkak.com/api/stripe` с событием `checkout.session.completed`.
3. Задеплойте с ключами:
   ```bash
   STRIPE_SECRET_KEY='sk_live_…' STRIPE_WEBHOOK_SECRET='whsec_…' ./deploy.sh wellness
   ```
4. Проверьте на тестовом ключе (`sk_test_…`) и тестовой карте `4242 4242 4242 4242`, затем переключитесь на боевой.

Доля предоплаты задаётся в `SITE.payments.deposit`. Выключить кнопку: `SITE.payments.stripe:false`.

## Аналитика и Search Console

GA4 и Яндекс Метрика загружаются только после согласия посетителя: баннер внизу, повторный выбор — «Настройки cookies» в подвале. Для немецкой версии это требование GDPR.

1. **Google Analytics:** analytics.google.com → создать ресурс → веб-поток `https://erkak.com` → скопировать идентификатор `G-…` в `SITE.analytics.ga4` (`content/core.mjs`).
2. **Search Console:**
   - search.google.com/search-console → «Ресурс с префиксом URL» → `https://erkak.com/` → способ «HTML-тег».
   - Код из `content="…"` вставьте в `SITE.verify.google` и задеплойте, затем нажмите «Подтвердить».
   - После подтверждения в «Файлах Sitemap» добавьте `https://erkak.com/sitemap.xml`.
3. **Яндекс Вебмастер и Метрика:** код подтверждения — в `SITE.verify.yandex`, номер счётчика — в `SITE.analytics.metrika`. Для русской аудитории это основной поиск.
4. **Bing Webmaster:** `SITE.verify.bing`. Bing и Яндекс получают новые адреса автоматически через IndexNow при каждом деплое.

## Экономика программ

Цены «от» пересчитаны по модели себестоимости: партнёр, проживание, трансферы, работа на месте, эквайринг. У каждого класса программ есть коридор маржи. Сама таблица с себестоимостью хранится **вне репозитория**, потому что он публичный. После изменения цены в таблице поменяйте её в `content/core.mjs`.

Сейчас в данных стоят заглушки и черновики.

- **Фото.** Сейчас это временная подборка из Unsplash: лицензия разрешает коммерческое использование без подписи, кадры грузятся с CDN Unsplash. Перед запуском:
  1. Сгенерируйте свои кадры по `content/PHOTO-PROMPTS.md`: одной командой `./wellness/photos.sh` (бесплатно через Pollinations или через Gemini при заданном `GEMINI_API_KEY`) или вручную, положив файлы в `photos-src/` с именем слота (`hero.jpg`, `dir-fishing.png`…).

  3. Выполните `node tools/og.mjs`: картинки для соцсетей перерисуются с настоящими фото.
